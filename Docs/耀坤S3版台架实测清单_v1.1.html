⚠️ 实测中踩到的「假 bug」（别重复排查）

现象真相
采样频率 显示 20 Hz / 1 Hz它是 loopRate（主循环频率），不是 IMU ODR。校准期、空闲期都正常，不要改 configureIMU()
mot 读数左右不对称、有 0 和 1是 desaturate() 削顶，四路失去可比性。验混控方向请用 Tools/mixer_sign_check.py 离线算
执行 ca 后姿态彻底失真六面没翻到位（48 秒跑完，人手跟不上）。救急：p IMU_ACC_SCALE_X/Y/Z 1 + p IMU_ACC_BIAS_X/Y/Z 0

✅ 热点名统一 YaoKun_ 前缀（AP 模式 + ESP-NOW 模式）

项值
前缀YaoKun_（Y、K 大写）
后缀芯片出厂 STA MAC 末两字节，例 1 号机 = YaoKun_F224（v1.1 修正）
默认密码1-2-3-4-5-6-7-8（连字符只是分隔，输入时不带；逐位：一、二、三、四、五、六、七、八）。源码以 ASCII 码表 {49,50,…,56,0} 构造；文档只写带连字符形式，不写连续数字串（过通道会被改写）
认名字只看开机日志 当前热点名：YaoKun_xxxx
改名字ap <热点名> <密码> + reboot

关键坑 1：ESP-NOW 模式也会起热点。 ESP-NOW 只能跑在 AP/STA 接口上，WiFi.mode(WIFI_AP) 一调，core 就自动起一个 ESP_ + MAC 后三字节的默认热点。旧版只改了 W_AP 分支，所以 ESP-NOW 模式下 飞机广播的是 core 默认名，现场认不出是谁家的。两条路径都要调 WiFi.softAP() 覆盖， 且必须在 mode(WIFI_AP) 之后调，否则会被模式切换冲掉。

关键坑 2：热点名后缀要读 eFuse 的 STA MAC（v1.1 已修）。 旧版用 WiFi.macAddress()，在 AP/ESP-NOW 上下文里返回的是 AP 接口 MAC：1 号机 wifi 显示 本机 MAC：80:65:99:DF:F2:24（STA），而 AP MAC 末两字节是 62:02， 于是热点名成了 YaoKun_6202，与 wifi 输出对不上，现场没法靠 MAC 认机。 现改用 esp_read_mac(ESP_MAC_WIFI_STA) 直接读熔丝位 → 恒为 YaoKun_F224， 现在可以放心用 wifi 的 MAC 末四位去对应热点名。

关键坑 3：NVS 里可能有占位符热点名。 1 号机实测发现 NVS 的 WIFI_AP_SSID 存着字面 "<热点名>"（当年照文档把占位符 当参数敲进了 ap <热点名> <密码>），导致自动命名被跳过、热点真的叫 <热点名>。 v1.1 增加校验：名字含 < > 或超过 32 字符即判脏值，自动清除并恢复自动命名。

🔴 真 bug：help 只显示品牌条，命令菜单整个不见

不是"代码里没写菜单"，是输出被截断。 三步凑一起才炸：

  1. motd 是一整条 C 字符串，1718 字节（品牌条 + 30 行命令），print() 里一次 Serial.print(buf) 整体写出；
  2. ESP32-S3 原生 USB 走 HWCDC，发送环形缓冲默认只有 256 字节（core HWCDC.cpp 的 setTxBufferSize(256)）；
  3. 本项目设了 setTxTimeoutMs(0)，HWCDC::write() 里 xRingbufferSend 以 0 tick 超时，装不下的部分当场 break 静默丢弃。

⇒ 只有前 ~256 字节能进缓冲，丢弃点正好落在品牌条末尾，所以看起来像"菜单丢了"而不是"打印断在半行"。

修法（console.ino，两处配合）：

  • setupConsole() 加 Serial.setTxBufferSize(4096)，整份 motd 一次塞进缓冲，USB 中断异步搬走，主循环仍零阻塞；
  • handleConsole() 命令收尾调 consoleFlushTail(150, ' ')——补写一个空格重新使能 USB 中断，把滞留的尾部数据带走。

踩坑警告：

  • ❌ 不要用 Serial.flush()：setTxTimeoutMs(0) 时它会走 flushTXBuffer(NULL, 0)，丢弃整个发送缓冲并自标"未连接"；
  • ❌ 排空判定不要写 >= 4096：TX 环形缓冲是 BYTEBUF 类型，可用空间最大值是"容量 − 1"，该条件永远不成立。

怎么用 mot 复位被污染的校准

p IMU_ACC_SCALE_X 1
p IMU_ACC_SCALE_Y 1
p IMU_ACC_SCALE_Z 1
p IMU_ACC_BIAS_X 0
p IMU_ACC_BIAS_Y 0
p IMU_ACC_BIAS_Z 0

执行后 st 应显示 横滚≈0° / 俯仰≈0°（实测 0.015° / −0.004°）。

1. 遥控器正确操作（★最容易被忽略）

实测确认：中文版遥控默认不使能控制输出，不使能就只发中位值。完整步骤：

  1. 开机 遥控器
  2. 进「对端发现」页，等飞机出现在列表里（扫描跨信道，能看到 ≠ 能通）
  3. 点选 那台飞机 → 建立连接
  4. 按「左按钮（辅助按钮）」 → 使能控制输出（enabled = !enabled）

⚠️ 界面上没有这个开关，是纯物理按键。 按一次开、再按一次关。

⚠️ 飞机重启后必须重新连接 + 重新使能（ESP-NOW 会话已清）。

信道必须一致

遥控器信道
中文版（ESP32-DJI-Dev-Yaokun20260815）1（Wi-Fi 默认，代码里没设）
英文版（ESP32-YKRC-Firmware）6（Control.hpp 里 esp_wifi_set_channel(6)）

固件默认 espnowChannel = 1。换遥控器时用 ch <1-13> 改飞机端：

> ch          → 信道：1
> ch 6        → ESP-NOW 信道已设为 6（遥控器必须一致），重启后生效

6. 油门量程（★首飞前必查）

MANUAL_CONTROL 满量程 ±1000，本工程 controlThrottle = m.z / 1000.0f。

摇杆位置期望实测
最低≈ −1.0✅ 观测到 −0.603（快速下拉采样点）
中位≈ 0.0✅ +0.010
最高≈ +1.0✅ +1.000

结论：±1000 全量程，无 0~1000 映射问题。

❌ 若实测是 0 / +0.5 / +1.0（只有正半程），不要起飞。

7. 电机与解锁

> mfr 0.1   → 右前      > mfl 0.1  → 左前
> mrr 0.1   → 右后      > mrl 0.1  → 左后
  • 四个电机都能转，位置对应正确（mfr 转的是右前那个）
  • 转向符合四轴 X 型布局
  • mot 未推油门时四路全 0

解锁：

  • 油门拉到最低 → arm 或遥控器解锁 → rc 中 解锁状态 = 1
  • 三短鸣 + 绿灯闪
  • 油门不在低位时尝试 arm → 打印「拒绝解锁：油门不在最低位」

8. 失联保护

  • 拔掉遥控器电源
  • 1 秒内长鸣 + 红灯慢闪
  • 10 秒后油门归零并自动上锁
