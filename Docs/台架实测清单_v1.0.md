## ⚠️ 实测中踩到的「假 bug」（别重复排查）

| 现象 | 真相 |
| --- | --- |
| `采样频率` 显示 20 Hz / 1 Hz | 它是 **`loopRate`（主循环频率）**，不是 IMU ODR。校准期、空闲期都正常，**不要改 `configureIMU()`** |
| `mot` 读数左右不对称、有 0 和 1 | 是 `desaturate()` **削顶**，四路失去可比性。验混控方向请用 `Tools/mixer_sign_check.py` 离线算 |
| 执行 `ca` 后姿态彻底失真 | 六面没翻到位（48 秒跑完，人手跟不上）。救急：`p IMU_ACC_SCALE_X/Y/Z 1` + `p IMU_ACC_BIAS_X/Y/Z 0` |

### 🔴 真 bug：`help` 只显示品牌条，命令菜单整个不见

**不是"代码里没写菜单"，是输出被截断。** 三步凑一起才炸：

1. `motd` 是一整条 C 字符串，**1718 字节**（品牌条 + 30 行命令），`print()` 里一次 `Serial.print(buf)` 整体写出；
2. ESP32-S3 原生 USB 走 HWCDC，发送环形缓冲**默认只有 256 字节**（core `HWCDC.cpp` 的 `setTxBufferSize(256)`）；
3. 本项目设了 `setTxTimeoutMs(0)`，`HWCDC::write()` 里 `xRingbufferSend` 以 0 tick 超时，装不下的部分**当场 break 静默丢弃**。

⇒ 只有前 ~256 字节能进缓冲，丢弃点正好落在品牌条末尾，所以看起来像"菜单丢了"而不是"打印断在半行"。

**修法**（`console.ino`，两处配合）：
- `setupConsole()` 加 `Serial.setTxBufferSize(4096)`，整份 motd 一次塞进缓冲，USB 中断异步搬走，主循环仍零阻塞；
- `handleConsole()` 命令收尾调 `consoleFlushTail(150, ' ')`——补写一个空格重新使能 USB 中断，把滞留的尾部数据带走。

**踩坑警告**：
- ❌ 不要用 `Serial.flush()`：`setTxTimeoutMs(0)` 时它会走 `flushTXBuffer(NULL, 0)`，**丢弃整个发送缓冲**并自标"未连接"；
- ❌ 排空判定不要写 `>= 4096`：TX 环形缓冲是 `BYTEBUF` 类型，可用空间最大值是"容量 − 1"，该条件**永远不成立**。

### 怎么用 `mot` 复位被污染的校准

```bash
p IMU_ACC_SCALE_X 1
p IMU_ACC_SCALE_Y 1
p IMU_ACC_SCALE_Z 1
p IMU_ACC_BIAS_X 0
p IMU_ACC_BIAS_Y 0
p IMU_ACC_BIAS_Z 0
```

执行后 `st` 应显示 横滚≈0° / 俯仰≈0°（实测 0.015° / −0.004°）。

## 1. 遥控器正确操作（★最容易被忽略）

实测确认：中文版遥控**默认不使能控制输出**，不使能就只发中位值。完整步骤：

1. **开机** 遥控器
2. 进「**对端发现**」页，等飞机出现在列表里（扫描跨信道，能看到 ≠ 能通）
3. **点选** 那台飞机 → 建立连接
4. **按「左按钮（辅助按钮）」** → 使能控制输出（`enabled = !enabled`）
   > ⚠️ **界面上没有这个开关，是纯物理按键。** 按一次开、再按一次关。
   > ⚠️ **飞机重启后必须重新连接 + 重新使能**（ESP-NOW 会话已清）。

### 信道必须一致

| 遥控器 | 信道 |
| --- | --- |
| 中文版（`ESP32-DJI-Dev-Yaokun20260815`） | **1**（Wi-Fi 默认，代码里没设） |
| 英文版（`ESP32-YKRC-Firmware`） | 6（`Control.hpp` 里 `esp_wifi_set_channel(6)`） |

固件默认 `espnowChannel = 1`。换遥控器时用 `ch <1-13>` 改飞机端：

```
> ch          → 信道：1
> ch 6        → ESP-NOW 信道已设为 6（遥控器必须一致），重启后生效
```

## 5. ESP-NOW 链路诊断（`wifi`）

```
> wifi
```
关键输出：
```
接收包数：7674                          ← ① 物理层收到几个包
接收字节数：16933                       ← ②
最近发包方 MAC：30:76:F5:EF:FE:08       ← ③ 应为遥控器 MAC
已解析 MAVLink 帧数：7674               ← ④
最近一帧消息 ID：69（MANUAL_CONTROL=69） ← ⑤
最近一帧来源 sysid：127                 ← ⑥ 耀坤遥控 = 127
MAVLink 链路在线：1
原生接收通道：1
接收队列积压：0 字节
```

**判读流程**：

| 现象 | 结论 |
| --- | --- |
| 包数 = 0 | 物理层没通 → 查信道、遥控器是否使能、peer 是否登记 |
| 包数 > 0，帧数 = 0 | 收到字节但组不成 MAVLink 帧 → 遥控器在 Raw 协议模式 |
| 帧数 > 0，msgid ≠ 69 | 遥控器只发 HEARTBEAT（未使能 / 不在控制页） |
| msgid = 69，rc 全 0 | 遥控器未使能（按左按钮），或 target 与 `mavlinkSysId` 不匹配 |

## 6. 油门量程（★首飞前必查）

`MANUAL_CONTROL` 满量程 **±1000**，本工程 `controlThrottle = m.z / 1000.0f`。

| 摇杆位置 | 期望 | 实测 |
| --- | --- | --- |
| 最低 | ≈ **−1.0** | ✅ 观测到 −0.603（快速下拉采样点） |
| 中位 | ≈ **0.0** | ✅ +0.010 |
| 最高 | ≈ **+1.0** | ✅ **+1.000** |

**结论：±1000 全量程，无 0~1000 映射问题。**

❌ 若实测是 `0 / +0.5 / +1.0`（只有正半程），**不要起飞**。

## 10. 出问题怎么查

| 现象 | 先看什么 |
| --- | --- |
| 遥控毫无反应 | `wifi` 的 `接收包数`；为 0 → 查信道（1 vs 6） |
| 遥控器显示已连接但飞机不动 | **按左按钮使能**（`enabled` 默认 false） |
| 收包正常但 rc 全 0 | `wifi` 的 msgid 是否 69；是 69 就按左按钮使能 |
| 飞机重启后遥控失效 | 需重新「对端发现 → 点选 → 按左按钮」，会话已清 |
| 油门前半程无反应 | 第 6 节量程问题，**不要起飞** |
| IMU 识别不出 | `2 号机` 查 SDA=9/SCL=8；接头是否插到底 |
| 界面出现英文 | 烧了英文版或上游原版，看开机第一行 |
| 烧完停在下载模式 | `esptool --after watchdog-reset run`，或拔插 USB |
